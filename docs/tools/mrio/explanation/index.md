# Explanation

This section provides information about MRIO, including its main functionalities, underlying concepts, and the methods used to process and analyze building information. Users can access the [MRIO website](https://multiroofs.github.io/mrio/) to visualize and analyze 3D building models.

## What is MRIO (MultiRoofs Input/Output)?
MRIO (MultiRoofs Input/Output) is a web-based tool developed as part of the MultiRoofs project for processing and preparation of 3D building models stored in CityJSON and CityJSONSeq formats.
MRIO's main purpose is to provide a user-friendly interface for inspecting, modifying, validating, and exporting 3D building data. MRIO supports several operations, including adding, renaming, and deleting building attributes, calculating roof surface areas and building volumes, and importing additional information from CSV files. It also provides a Roofer → MultiRoofs conversion function, which prepares building models generated by Roofer for use within the MultiRoofs workflow by merging BuildingPart geometry into parent Building objects and adding relevant rooftop information.
Another important feature is the validation functionality, which allows users to check whether their CityJSON data meets the required structural and schema requirements. After processing, users can export their datasets for further analysis, visualization, or use in other applications.

## Why do we need MRIO?
3D building models often contain complex geometric structures and large amounts of attribute information. Modifying these files manually can be time-consuming and may introduce errors, particularly when working with multiple buildings or preparing datasets for different applications.
MRIO addresses these challenges by providing a centralized interface for common data-processing operations. It reduces the need for manual file editing, helps users identify data issues through validation, and supports the preparation of consistent building and rooftop information.
Overall, MRIO acts as a bridge between 3D building model generation and further data analysis or visualization, making CityJSON-based workflows more accessible, efficient, and easier to manage for both technical and non-technical users.
## Required Input Files for MRIO
MRIO works with 3D building models stored in
<span style="color: #D32F2F; font-weight: 600;">CityJSON</span>
and
<span style="color: #D32F2F; font-weight: 600;">CityJSONSeq</span> formats. To use MRIO, users must upload a valid file in one of these supported formats.
### 1. CityJSON File ('.city.json')

CityJSON is a JSON-based format used to store and exchange 3D city models, including buildings, their geometries, and associated attributes.

A CityJSON file typically contains:

- CityObjects: Buildings, BuildingParts, and other city objects.

- Geometry: The 3D geometric representation of buildings, including roof surfaces, walls, and ground surfaces.

- Attributes: Additional information about buildings, such as building height, construction year, roof characteristics, and volume.

- Metadata: Information about the dataset, including its Coordinate Reference System (CRS).

MRIO allows users to upload CityJSON files, inspect their contents, modify attributes, validate the data, and export the processed results.

### 2. CityJSONSeq File ('.city.jsonl')

CityJSONSeq (CityJSON Sequence) is a line-oriented format for storing and processing 3D city models. Unlike standard CityJSON, which stores the complete model in a single JSON document, CityJSONSeq organizes the data into separate JSON records, with each record written on a single line.

This format is particularly useful for processing large datasets and is one of the output formats generated by Roofer, a tool used to reconstruct 3D building models from building footprints and point-cloud data.

For example, Roofer can generate a file named 085289_447042.city.jsonl, which can be uploaded directly into MRIO for further processing.

MRIO supports operations on CityJSONSeq datasets, including attribute management, validation, and conversion to the MultiRoofs data structure.

### 3. CSV File (.csv) — Optional

In addition to CityJSON and CityJSONSeq, MRIO supports importing attribute information from CSV  files.

CSV files are used when users want to add external information to existing CityObjects, such as building classifications, rooftop characteristics, or other numerical and descriptive attributes.

The CSV file must contain a column identifying the CityObjects so that MRIO can match each row with the corresponding object in the uploaded CityJSON dataset.
