# Add the API reference of a non-Python tool

For tools that are not Python (Rust, TypeScript, C++, web services, third-party
tools), the reference is generated by the tool's own documentation generator
(rustdoc, TypeDoc, Doxygen, Swagger UI, Sphinx, pdoc, and so on). This site does
not run those generators. You choose one of two options:

| Situation | Option |
|---|---|
| The reference is already online | **A. Link to it.** Preferred: always up to date, nothing to maintain here. |
| The reference is not online anywhere | **B. Paste the generated HTML** into this repository. |

## Option A. Link to published docs

Write `docs/tools/<your-tool>/reference/index.md` like this:

````markdown
# API reference

my-tool publishes its own reference.

```{button-link} https://your-org.github.io/my-tool/
:color: primary
:shadow:

Open the my-tool API reference
```
````

Typical addresses:

| Generator or host | Usual address |
|---|---|
| A tool repository published with GitHub Pages | `https://<org>.github.io/<repo>/` |
| Rust crate on crates.io | `https://docs.rs/<crate>` |
| FastAPI service | `https://<service>/docs` (Swagger UI) or `/redoc` |
| Third-party tool | Its official documentation |

```{tip}
If the tool's own docs are built with Sphinx, you can also link to individual
objects from the written pages through intersphinx. Ask the docs maintainers to
add the site to `intersphinx_mapping` in `docs/conf.py`.
```

## Option B. Paste generated HTML

### 1. Generate the HTML in your tool's repository

Use your usual generator. Examples:

| Language | Command | Output folder |
|---|---|---|
| Rust | `cargo doc --no-deps` | `target/doc/` |
| TypeScript | `npx typedoc --out out src/index.ts` | `out/` |
| C / C++ | `doxygen Doxyfile` | `html/` (as set in the Doxyfile) |
| Java | `javadoc -d out ...` | `out/` |

The output must work when opened from a folder: open its `index.html` in a browser
from your disk and click around before pasting. Absolute links (starting with `/`)
break on GitHub Pages.

### 2. Paste it into this repository

Copy the **content** of the output folder to:

```
docs/_extra/reference/<your-tool>/
```

so that `docs/_extra/reference/<your-tool>/index.html` exists. Replace the whole
folder on every update: delete the old one first, so that removed pages
disappear too.

Everything under `docs/_extra/` is copied to the site unchanged, so the folder
above is published at `<site address>/reference/<your-tool>/index.html`.

```{note}
Rust's `cargo doc` writes one folder per crate plus shared files. Paste all of
`target/doc/`, then link to `reference/<your-tool>/<crate_name>/index.html`
(the crate name uses underscores).
```

### 3. Link it from your reference page

Write `docs/tools/<your-tool>/reference/index.md`:

```markdown
# API reference

<a class="sd-btn sd-btn-primary sd-shadow-sm" href="../../../reference/<your-tool>/index.html">Open the my-tool API reference</a>
```

Use exactly this HTML link. A normal Markdown link (`[text](...)`) does not work
here: Sphinx looks for a page with that name, does not find one, and produces a
broken link. The `../../../` climbs from `tools/<your-tool>/reference/` back to the
root of the site.

### 4. Check

Build, open your tool's reference page and click the button. It should open the
pasted pages.

### What to expect from pasted HTML

- It keeps its own look and navigation. There is no sidebar of this site inside it.
- It is not included in this site's search.
- It is a snapshot: paste it again after each release.
- Generated HTML is large and every paste adds to the repository size. If the tool
  gets its own published docs later, switch to option A and delete the folder.
